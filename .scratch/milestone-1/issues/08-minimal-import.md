# Minimal Import: a cup diagram becomes a Model

Status: resolved
Type: task
Blocked by: 03, 07

A Node script on Dad's computer: takes a Source from `import/inbox/` (gitignored), asks the Claude API (latest Opus) for Fold calls per Step with Step text in FoldLab's own words, replays every Step in the engine, and writes the Model file to the published Library only if every Step replays. Otherwise it records a Failed import with the reason. A per-run cost cap (default $5) stops the run. API key from an environment variable, never committed.

- **What Dad runs.** Put one cup Source in `import/inbox/` named `cup` (`cup.pdf`, `cup.png`, `cup.jpg`, or a folder `cup/` of page images), then in PowerShell: `$env:ANTHROPIC_API_KEY = "sk-ant-..."; npm run import`. The file's name is the Model's id, so it must be `cup` to replace the stand-in. `npm run import -- cup.pdf` imports one Source by name (again, if it is already imported); `npm run import -- --cap 2` sets the run's cost cap in dollars (default $5).
- **What changes when it succeeds.** `src/library/cup.json` is overwritten with the imported Model and `src/library/cup.recipe.json` appears beside it (the name, Source credit, Paper and engine calls Claude gave, in FoldLab's own words; safe to publish). Nothing else: `recipes.ts` picks up any `*.recipe.json` and lets it replace the stand-in of the same id, so the "fresh" test then ties `cup.json` to the imported recipe, and `library.ts` already lists `cup`. Then `npm test`, `npm run dev`, fold it against the Source, commit `src/library/`. **Expect `npm test` to need attention then:** `library.test.ts` has tests written against the stand-in's four Steps (the walk, "back first, then front", and the 10 expected-failure registrations by Step); with a differently shaped imported cup they must be rewritten against it and `cupRecipe` deleted. I left them alone because ticket 14 is about to change the same lines. A Model with a new id also needs one line in `library.ts` (`FILES`); a test says so.
- **What happens when it fails.** Nothing is written to `src/library/` (what was there stays), and `import/work/failed/cup.json` (gitignored) records the Failed import: Source name, when, the reason as a kind and a sentence, what it cost, and Claude's raw answer. Kinds: `claude-refused`, `cut-short`, `unreadable-answer`, `source-unreadable` (Claude says it cannot read it), `unsupported` (below), `invalid` (not a Model recipe, every problem listed), `refused` (the engine, with Step and Fold), `unrecordable`, `too-large`. The Source stays in the inbox for retry; a later success deletes the record. There is one request per Source and no second try with the engine's refusal fed back; given how often diagrams are misread (ADR 0003) that loop is the obvious next step, but it is not in this ticket.
- **How it is built.** `src/import/import.ts` is the run (`runImport`): finds the Sources, checks the cap, asks, turns the answer into a recipe, calls ticket 07's `buildModel`, writes or records. `src/import/answer.ts` is the system prompt, the answer's JSON schema and the conversion to a `ModelRecipe`. `src/import/claude.ts` is the only file that imports the SDK; `scripts/import.mjs` wires them like `npm run library`. The request, per the claude-api skill: `claude-opus-5-5`, adaptive thinking, effort high, the answer held to the schema by structured outputs, streamed, `max_tokens` 32,000, the Source as base64 image/PDF blocks before the question, and `fallbacks: "default"` (beta `server-side-fallback-2026-07-01`) so a Source that Opus 5.5's safety classifiers decline is retried by the API on the model Anthropic recommends. Remove that one line if Dad would rather a decline simply be a Failed import.
- **The cost cap.** Before each Source the request's input tokens are counted (the API's token count, which sends nothing to a model) and priced as if the answer ran to the full 32,000 tokens at the dearest price in play ($5/$25 a million); if that could pass the cap, the run stops there. After each answer the tokens Claude reports are priced per model (Opus 5.5 $4/$20; a fallback $5/$25) and added up; at or past the cap the run stops. Sources not sent are listed as not tried and are not Failed imports. The dollar figures are estimates from the skill's price table (cached 2026-10-06), kept in `import.ts`; the Console is the bill.
- **The API key** is read from the `ANTHROPIC_API_KEY` environment variable and passed to the SDK explicitly; no file, no argument. Without it the run stops before anything is sent or written.
- **Decision: turn over, rotate and fold-and-unfold are not added to the Model.** Import asks only for valley and mountain calls, and tells Claude not to work around anything else: such a Fold is answered with just its type, and the Source becomes a Failed import naming it ("Step 3, Fold 1 is a turn over"), before the engine is run. Reasons: carrying them means the recorder (untried on them, and already wrong on stacks, ticket 14), the player and the page (ticket 06's files, and the edge-swipe gesture DESIGN.md asks for), which is its own ticket; and quietly rewriting "turn over, fold the flap down" as a mountain Fold would break the glossary's "a Step exactly as the Source shows it". **Consequence Dad should know:** a cup Source that says "turn over" will fail honestly. Pick one that folds the back flap behind (as the stand-in does), or do the turn-over ticket first.

**2026-11-13, agent (review fixes):** Changes to Import after code review, on `milestone-1-review-fixes`. Still no real Import run; `claude.ts` is still only compiled.

- **No fallback.** `claude.ts` no longer sends `fallbacks: "default"` (or its beta). One request is one billed pass on Opus 5.5, which is what the cost cap prices before sending; with the fallback a declined Source could bill two passes and pass the cap. A Source Claude declines is now simply a Failed import (`claude-refused`) with the API's reason. The fallback price rows are gone; a model the price table does not know is still priced at the dearest ($5/$25).
- **Nothing to import is not an error.** With no Source to try (empty inbox, or everything already imported) the run says "Nothing to import" and succeeds, whether or not `ANTHROPIC_API_KEY` is set. The key is asked for only when there is a Source to send.
- **The Claude API failing on a Source that was sent** now records a Failed import (`claude-api`, with the API's message) and still stops the run; the Sources after it are not tried. What that request was billed is not known, so its input (the token count priced at the dearest rate) is counted as spent and the record and the output say so. If the API fails while counting tokens, nothing was sent: the run stops and that Source is "not tried", not a Failed import.
- **A stopped run names the Sources not tried** in its printed message (cost cap, missing key, API failure).
- **Writing to the Library is all or nothing.** `<id>.json` and `<id>.recipe.json` are written under temporary names (`.tmp`) and renamed into place; if anything fails the temporary files are removed, whatever was there before is put back, and the Source becomes a Failed import (`library-write`) instead of the run throwing.
- **For Dad: a failed re-import keeps the earlier Model.** If `cup.json` is already in the Library (the stand-in, or an earlier import) and importing `cup` again fails, the earlier `cup.json` stays and a Failed import is recorded for the same id. GLOSSARY says a Failed import "never appears in the Library"; here the Model in the Library is the earlier good one, not the failed try, and deleting a good Model seemed worse. The Failed record now carries `earlierModelKept: true` and the output says the Library still has the Model from before. Say if a failed re-import should remove it instead.
- **Cleanup, no behaviour change:** prompt and schema wording follows GLOSSARY (Paper, Step text; no "sheet" or "instruction"); the supported Fold types are one list (`FOLD_CALL_TYPES` in `model.ts`) read by the format, its checks and the answer format; `scripts/typescript.mjs` holds the Vite loader the three scripts shared.
- **Checks.** `npm run typecheck`, `npm test` (22 files: 324 passed, 15 expected failures, 2 skipped) and `npm run build` pass. `npm run import` with an empty inbox and no key prints "Nothing to import" and exits 0; `npm run library` rebuilds `cup.json` byte for byte.
